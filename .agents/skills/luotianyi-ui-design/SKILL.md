# 洛天依 UI 设计与验收

先读取仓库 `docs/项目总控.md`、任务对应产品规格、安全约束和 `git status`。真实应用是 C# / WPF / net48，使用 .NET 10 SDK 构建。Planner 样式是 `PlannerTheme.cs` 中的 Brushes、XAML Style/ControlTemplate 和 C# 控件树，不是 CSS。不要引入 WebView、网页组件库或改变目标框架来美化页面。

本 Skill 组织设计与验证，不是新的业务规格。当前用户需求优先；存档、日历计算、班休、提醒、闹钟及事件处理保持原样，除非用户明确要求修改。不能用参考图中的示例日期替换真实日期逻辑。

## 必须完成的闭环

1. 打开并亲自观察用户参考图（本地用 `view_image`），记录原图尺寸；读对应页面实现和现有设计 token。参考图缺失时报告，不能声称已比较。读 [视觉准则](references/design-review.md)。
2. 在本轮证据目录写 `design-contract.md`：页面任务、视觉语言、主要焦点、分区比例、对齐轴、中文字体/字号/字重、间距、颜色语义、圆角/边框/阴影、各交互状态。标记“从图观察”“从代码确认”“推断”，不要把推断当用户决定。参考图文字与当前业务冲突时保留业务。
3. 先截图当前实际窗口，列出最显著的差距及代码位置。只选本轮相关控件；优先调整布局比例与层级，再调整字体、留白、颜色、细节。复用现有 token 与模板，减少各页重复魔法数。
4. 小步实现、编译及相称的测试。按 [操作与比较](references/tool-workflow.md) 运行真实 PlannerWindow 隔离宿主；其他窗口沿用其专用 QA。不能把自制 HTML 模型冒充实际应用。
5. 操作真实窗口进入目标状态并截图。至少覆盖本轮默认状态和涉及的弹层/选中/禁用/错误/长文本状态。逐次观察 UIA 后再操作，不猜测句柄或复用过期索引。隔离样例数据不得写入真实用户存档。
6. 用 `view_image` 实际查看原图、当前截图和差异/叠图。相同比例/相同内容的基线走 pixelmatch；设计参考图按分区、比例和文字层级比较，不能把像素百分比当审美评分。不同大小必须明确裁切/对齐依据，不可静默拉伸或自动覆盖基线。
7. 写 `review.md`：每个差异的区域、证据、严重程度、修改措施；修复最重要差异后重新运行、重新截图。新结果替换旧结论，旧证据保留。不得修改一次样式后直接宣布完成。
8. 完成条件：编译/测试通过；实际截图已观察；无裁切/遮挡/错位；层级和参考图的主要比例、色彩、文字节奏一致；关键交互未退化；已知差异逐项解释。若尚有重要差异就继续修正；工具阻塞或需产品判断时如实交接，不伪造通过。功能通过不等于视觉通过。
9. 更新总控和开发日志，按仓库要求提交并推送。截图、用户参考图、测试存档留在被忽略的 `artifacts/ui-review/`；只提交工具和脱敏结论。

## 必须区分的证据

- WPF RenderTargetBitmap：控件渲染，不能证明遮挡、系统合成、真实 DPI、鼠标操作正确。
- 真实桌面窗口裁图：能证明当时最终可见画面；必须检查遮挡与鼠标光效污染。
- UI Automation InvokePattern：真实控件的无障碍操作；不能冒充物理鼠标、拖拽或键盘焦点验收。
- Pixelmatch：像素变化；不能证明美观、语义或业务正确。低比例也可能掩盖严重局部问题。
- 125/150% 输出渲染不等于切换了显示器缩放。真实多屏/DPI 未测试时必须注明。

当前机器的 computer-use UIA 读取和激活可用，但截图报 `SetIsBorderRequired ... 0x80004002`、click 报 `coordinate input geometry is unavailable`。使用已验证的受限回退，不能修改系统安全设置或绕过 PowerShell 执行策略。详见工具文档。
