# 视觉判断与 WPF 实现准则

## 先看构图，再看组件

先描述视线从哪里开始、下一步在哪里、主次信息占多大面积。月历的主角是日期与内容，闹钟的主角是时间与状态；不要把每个信息块都包成同等分量的卡片。卡片用于独立可交互实体；区块分组优先通过留白、对齐和小标题完成。不要为“精致”叠加渐变、投影、描边、图标和装饰标签。

对参考图按窗口外框、标题导航、主内容、辅助区、操作区分解；记录各区占比和共同对齐边。边框数量、文字密度、色彩面积同样需要比较。用“侧栏约占 28%，标题基线与主区左缘一致”这种可验证描述，不写“更高级”。

## 排版与间距

- 优先使用现有可用的中文字体，检查中文、数字、英文混排基线。禁止未经授权下载商业字体或用装饰字体覆盖全页。
- 为标题、正文、辅助说明定义有限字号/字重层级；先检查缩小到整窗时能否辨认主信息，再看 100% 文字清晰度。
- 使用少量可解释的间距档位，组内小、组间大；参考图明确时以图中关系为准。不要机械地把所有间距变成同一个值。
- 文案真实时验证一行、两行、最长合法内容和空态。不要以删减用户内容或改变标题上限解决溢出。
- WPF 的 DIP 与截图物理像素需记录转换；检查 LayoutRounding、文本裁切、Auto/星号布局、滚动边界，避免用固定 Height 掩盖问题。

## 色彩与控件

沿用 PlannerTheme 的语义色；工作/休息、今天/选中、普通/危险必须可分辨。一个主强调色不代表所有标题、日期和按钮都必须同样醒目。文字与背景要实际核对对比度；普通文字以至少 4.5:1 为审查目标，不能靠“有点淡比较精致”接受不可读文字。大字、禁用态例外需明确说明。

控件的默认、hover、pressed、focus、disabled、selected 必须能区分；不要只检查默认截图。检查 Toggle 的状态含义、危险操作层级、弹窗取消/确认位置和滚动后按钮可达性，不改现有交互语义。

## 原生无障碍与交互复核

通过 UIA 检查按钮是否有可理解的 Name/说明，输入是否有标签，Tab/Shift+Tab 是否按视觉顺序移动，焦点能否看到，Esc/取消是否按既有规则工作。图标按钮的可视子文本不等于已经具备可靠的可访问名称。发现缺项先记录，UI 美化时在范围内修正。读屏器与高对比模式没有实际测试就写未验证；不可把网页 axe 检查称为 WPF 无障碍验收。

## 差异记录表

每条包含：区域、参考证据、当前证据、原因、严重度、下一次修改、复测截图。先处理影响主要布局/可读性/操作的差异，再处理图标线宽等细节。对于不同日期、系统抗锯齿或字体导致的差异，解释原因，禁止仅提高阈值让测试通过。
