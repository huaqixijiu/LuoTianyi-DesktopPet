## 1. 目录职责

| 目录 | 内容 | Git | 发布包 |

## 3. 新素材归置规则

收到新素材后：

1. 记录来源目录和大致用途。
2. 检查动画清单、状态映射和构建脚本，判断是否实际使用。
3. 只复制实际使用或需要重建的文件到 `原素材/`。
4. 按 `animations/`、`models/`、`ui/` 分类，尽量保留原始名称。
5. 同名文件先比较 SHA-256，禁止未经确认覆盖。
6. 未使用的素材留在原目录，不迁移、不删除。
7. 更新 `docs/原素材索引.md`。
8. 输出来源、目标、文件数量、哈希和用途。

迁移使用复制，不使用移动。候选素材保留到项目完成后，由用户手动清理。

## 4. 运行时数据

安装版用户数据位于 `%LOCALAPPDATA%\LuoTianyiPet\`；便携版数据位于程序旁的 `UserData\`。设置、提醒、备份、损坏文件保留件和按日日志均属于用户数据，构建脚本不得修改或清理。

缓存、临时文件和崩溃转储使用系统用户目录或 `%TEMP%`。卸载和数据清理必须遵循产品约定，不得由重构脚本擅自执行。

## 5. Git 规则

以下内容不进 Git：

- `原素材/`
- `候选素材_官方/`
- `artifacts/`
- `.local-tools/`
- `bin/`、`obj/`、`publish/`
- 日志、缓存、崩溃转储和临时文件
- 本地 `AGENTS.md`

源码、测试、配置、工具、正式运行时资源和正式文档进 Git。PNG、WebP、GIF、音视频、模型和压缩包使用 Git LFS；代码、配置和文档不使用 Git LFS。

提交前检查：没有原素材、用户数据、密钥、构建产物和临时文件；构建、测试及相关 QA 已完成；项目总控和开发日志已同步。

## 6. 发布包规则

发布包包含应用程序和 `assets/` 下的正式运行时资源，包括运行时动画、加工动画、UI、清单、正式音频、对象和光标。

发布包明确排除：`原素材/`、`候选素材_官方/`、`artifacts/`、`.local-tools/`、`docs/`、`tools/`、`tests/` 和 `config/`。

便携包、MSIX 和旁加载包的产物统一写入 `artifacts/`，不得写入项目根目录。

## 7. 构建和加工流程

```text
原素材 → 工具临时目录 → assets/animations/processed → assets/animations/runtime → 发布包
```

构建输入路径必须由配置或工具参数明确声明。预览输出不得写回原始输入目录。完成加工后，正式运行时只读取 `assets/` 下的资源。

## 8. 命名规范

- 代码目录使用 PascalCase，Python/Node 文件使用 snake_case。
- 动画 ID 使用小写 kebab-case。
- 原始素材尽量保留来源名称。
- 运行时资源名称必须稳定，不能为了美化 UI 随意改名。
- 重命名文件必须全局搜索引用并同步更新配置、脚本、文档和打包规则。

## 9. 结构变更流程

修改目录、路径、资源引用、存档格式、快捷键、托盘、自启、动画或用户可见行为前：

1. 阅读本文和项目总控。
2. 全局搜索引用并列出受保护资源。
3. 说明影响、风险、回滚方式和验证步骤。
4. 删除、移动、重命名或改变外部路径前先确认。
5. 每次只完成一个可验证阶段。
6. 同步更新 `DEVELOPMENT.md`、`docs/项目总控.md` 和 `docs/开发日志.md`。
